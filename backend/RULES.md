# Бэкенд ФСП Оренбургской области — правила разработки

Читай перед любой правкой в `backend/`, `infrastructure/` и `manage/`. Устройство областей и их список — [README.md](README.md), модели — [infrastructure/README.md](../infrastructure/README.md), подробные соглашения — [docs/000_conventions.md](../docs/000_conventions.md). Если правила здесь и там расходятся, главнее этот файл.

## Главные правила

1. **Репозиторий — только работа с хранилищем: Postgres, Redis или файловое хранилище (S3).** Один метод репозитория — один запрос либо одна компактная группа действий с ним (удалить и вставить, увеличить счётчик и выставить срок). Решения, правила, расчёт дат и сроков, статусы, повторы, выбор «что делать дальше» — в `domain/`. Если метод репозитория начинает что-то решать, вынеси решение в домен, а репозиторию оставь запрос с готовыми значениями.
2. **Без лишних функций-хелперов.** Не заводи функцию ради одной-двух строк, которые читаются и так. Хелпер оправдан, когда он нужен в нескольких местах или прячет действительно сложную вещь. Модульные `_x()` по одной на каждый чих — не наш стиль.
3. **У каждой функции и метода — докстринг.** Одна-две строки по-русски: что делает и что возвращает, если это не очевидно из названия. Комментариев внутри кода не пишем: докстринга достаточно. Классы с логикой тоже получают докстринг; схемы Pydantic и ORM-модели — нет, их поля говорят сами за себя.

```python
async def claim(self, qualification_id: UUID, threshold_days: int) -> bool:
    """Отмечает напоминание о сроке отправленным; False, если такое уже было."""
```

## Слои

```
features/        фича = папка с router.py и schemas.py; схемы между фичами не шарятся, при нужде дублируются
domain/          классы с логикой: проверки, транзакции (UnitOfWork.commit), аудит, уведомления
repositories/    хранилища данных, и только они: pg_ Postgres, red_ Redis, s3_ файлы
clients/         внешние сервисы, которые не хранят наши данные: почта (SMTP), Telegram Bot API, Codeforces API
dependencies.py  сборка сервисов области для FastAPI Depends
```

- Импорт только вниз: `features → domain → repositories / clients → infrastructure`. Роутер вызывает только домен, репозитории и клиенты вызывает только домен. Клиент — тонкая обёртка над чужим API без решений, как и репозиторий.
- Домен и репозитории возвращают ORM-модели или простые кортежи и датаклассы строк; копии моделей не заводим.
- Доменные классы называются по сущности, без «Service»: `Contest`, `Files`, `Notifications`.
- Даты «сегодня» и границы дней считаются в домене по Оренбургу (`Asia/Yekaterinburg`) и передаются в репозиторий готовыми.

## Код

- Python 3.12, FastAPI, SQLAlchemy 2.0 async, Pydantic v2.
- Аргументы эндпоинтов — через `Annotated[...]` (`Body`, `Query`, `Path`, `Depends`). Доступ — `CurrentUserDep`, `require_role(Role.X)`.
- Ошибки — наследники `AppError` из `core/errors.py`.
- Значимые действия пишутся в журнал `Audit.write(...)` в той же транзакции; новое действие — в `audit/domain/actions.py` с русским названием.
- Уведомления — только через `Notifications`, до `commit()`; новый тип — в `notifications/domain/types.py`.
- Новая модель — файл в `infrastructure/<группа>/`, импорт в `backend/main.py`, строка в `infrastructure/README.md`.
- Оформление моделей одно для всех: `__tablename__` и `__table_args__` (по элементу на строку), пустая строка, все поля подряд — каждое поле в одну строку, какой бы длинной она ни была. Затем каждая связь `relationship(...)` отдельным блоком через пустую строку: по аргументу на строку с запятой в конце. В конце свойства и методы.

```python
class SquadMemberModel(Base):
    __tablename__ = "squad_members"
    __table_args__ = (
        UniqueConstraint("squad_id", "user_id", name="uq_squad_members_squad_user"),
    )

    id: Mapped[int] = mapped_column(Integer, primary_key=True, autoincrement=True)
    squad_id: Mapped[int] = mapped_column(ForeignKey("squads.id", ondelete="CASCADE"), index=True)

    user: Mapped[UserModel] = relationship(
        lazy="selectin",
    )
```
- Демо-данные — раздел в `manage/seed/seed.sql`, файлы — в `manage/seed/<тип>/`.

## Перед тем как сказать «готово»

- `.venv/Scripts/pyright.exe` — 0 ошибок.
- Если менялся API, данные или запуск — собрать Docker с нуля и проверить затронутые эндпоинты запросами.
- Коммит, merge и push — только по команде пользователя.
