# Бэкенд

FastAPI-приложение одним процессом: API, фоновые задачи (очередь писем и Telegram, напоминания о сроках, синхронизация Codeforces) и Telegram-бот запускаются в `main.py`. Модели базы — в `infrastructure/`, запуск в Docker и демо-база — в `manage/`.

Код разбит на области. Внутри каждой слои идут строго сверху вниз, импорт только вниз:

```
features/        фича = папка с router.py (эндпоинты) и schemas.py (тела запросов и ответов); схемы между фичами не шарятся
domain/          логика области: проверки, транзакции, аудит, уведомления
repositories/    хранилища данных; приставка — где данные: pg_ (Postgres), red_ (Redis), s3_ (файлы)
clients/         внешние сервисы: почта, Telegram Bot API, Codeforces API (есть только там, где нужны)
dependencies.py  сборка сервисов области для FastAPI Depends
```

Области сгруппированы по смыслу так же, как модели в `infrastructure/`.

| Группа | Область | Что делает |
|---|---|---|
| **Основа** | `core` | Конфиг, подключения к Postgres и Redis, единый формат ошибок, IP клиента, проверка здоровья |
| **Аккаунт** | `auth` | Регистрация, вход и выход, сессии, роли и их подтверждение федерацией, почта, восстановление пароля |
| | `people` | Страница человека, лента выступлений, привязка и синхронизация Codeforces |
| | `consents` | Согласия законных представителей и их проверка федерацией |
| **Общие службы** | `audit` | Журнал действий и его просмотр федерацией |
| | `files` | Загрузка файлов с проверкой типа, выдача по постоянной или подписанной ссылке |
| **Справочники** | `dictionaries` | Чтение справочников и управление ими: добавление, правка, архив |
| **Соревнования** | `contests` | Каталог соревнований, кабинеты организатора и федерации, жизненный цикл, верификация с баллами |
| | `events` | События федерации и общая лента календаря: события вместе с соревнованиями |
| **Участие и итоги** | `applications` | Заявки: личные и командные, приглашения, подача тренером, модерация |
| | `results` | Места участников и протокол в xlsx |
| | `documents` | Дипломы, сертификаты, благодарности, справки: выпуск, PDF, проверка по QR |
| | `readiness` | Чек-лист готовности соревнования для организатора и федерации |
| | `disputes` | Апелляции на места и рапорты о нарушениях: решение федерации, правка протокола, санкции и отстранение |
| | `ratings` | Рейтинг спортсменов по дисциплинам и группам по правилам федерации: сезон, коэффициент стабильности, объяснение итога |
| | `squads` | Сборные по приказу: состав из рейтинга, метки на странице человека |
| **Судьи и разряды** | `qualifications` | Разряды и судейские категории: основание из протокола, приказ, QR-проверка; судейские коллегии с конфликтом интересов и документы судей к протоколу, напоминания о сроках |
| | `evsk` | Правила ЕВСК, претенденты на разряд по местам, личный путь спортсмена |
| **Спортивная подготовка** | `profiles` | Организации, спортивный профиль, связи тренер ↔ спортсмен, антидопинг РУСАДА |
| | `training` | Программы и тренеры организаций, учебно-тренировочные группы, журнал занятий, нормативы ФССП и аттестация |
| | `registry` | Реестр федерации и отчёт о численности занимающихся по годам |
| | `deadlines` | Сроки по ролям и фоновые напоминания: закрытие заявок, премии Губернатора, отчёты, разряды, РУСАДА |
| **Контент** | `news` | Новости: лента, теги, редактор статей |
| **Уведомления** | `notifications` | Уведомления в кабинете, настройки каналов, очередь писем и Telegram, Telegram-бот |
| **Аналитика и отчёты** | `analytics` | Дашборд федерации и выгрузка в xlsx |
| | `reports` | Отчёт по человеку в PDF и xlsx: выступления, подопечные, судейство, разряды, документы, сборные |

| | `requirements.txt` | Зависимости Python |

Новая область — папка со слоями выше, строка в этой таблице и роутер в `main.py`.

## Правила кода

- **Репозиторий только работает с хранилищем.** Один метод — один запрос или компактная группа действий с ним. Решения, статусы, расчёт дат и сроков — в `domain/`.
- **Роутер вызывает только домен**, домен — репозитории и клиенты. Схемы Pydantic между фичами не переиспользуются.
- **Транзакция в домене**: действие, запись в журнал (`Audit.write`) и уведомление (`Notifications`) сохраняются одним `commit()`. Письма и Telegram уходят через очередь `outbox`.
- **Ошибки** — наследники `AppError` из `core/errors.py`, клиент получает `{"error": {"code", "message", "fields"}}`.
- **Даты «сегодня»** считаются в домене по Оренбургу (`Asia/Yekaterinburg`) и передаются в репозиторий готовыми.
- **У каждой функции и метода — докстринг** по-русски в одну-две строки; комментариев внутри кода нет.
- Аргументы эндпоинтов — через `Annotated[...]`, доступ — `CurrentUserDep` и `require_role(Role.X)`.
- Новое действие журнала — в `audit/domain/actions.py` с русским названием, новый тип уведомления — в `notifications/domain/types.py`.

## Тесты

`tests/` — pytest: `test_unit_rules.py` проверяет доменные правила без базы, `test_api_*.py` — сценарии на поднятом стенде (адрес — `FSP_TEST_API`, по умолчанию `http://localhost:8000/api/v1`). Зависимости — `requirements-dev.txt`. Запуск из папки `backend`: `python -m pytest`.

## Проверка

```bash
.venv/Scripts/pyright.exe   # Windows; на Linux и macOS — .venv/bin/pyright
```

Pyright должен проходить без ошибок. После изменений API или данных — пересобрать Docker-образ с нуля и проверить затронутые эндпоинты в Swagger (`/docs`).
