# Фронтенд

Сайт федерации и кабинеты ролей: React 19, TypeScript (strict), Vite 8, Tailwind CSS 4, React Router 7, TanStack Query 5. Сторонних UI-библиотек нет — набор компонентов свой, в оформлении ФСП, тёмная и светлая темы.

## Запуск

```bash
npm install
npm run dev          # http://localhost:5173, запросы /api проксируются на бэкенд
```

Адрес бэкенда для прокси — переменная `VITE_PROXY_TARGET` (по умолчанию `http://localhost:8000`). Бэкенд запускается в Docker, см. корневой README.

| Команда          | Что делает                                        |
| ---------------- | ------------------------------------------------- |
| `npm run dev`    | Dev-сервер                                        |
| `npm run build`  | Проверка типов и сборка в `dist/`                 |
| `npm run check`  | `tsc`, ESLint, Prettier и сборка — перед коммитом |
| `npm run format` | Prettier                                          |

## Устройство

Feature-Sliced Design, импорт только вниз и только через `index.ts` слоя (проверяет ESLint):

```
src/
  app/        маршруты, раскладки сайта и кабинета, провайдеры, стили и токены тем
  pages/      страницы: сайт, кабинеты ролей, публичные проверки документов и разрядов
  widgets/    крупные блоки: оболочка кабинета с меню, календарь, рейтинг спортсмена
  features/   действия пользователя: заявки, модерация, места, апелляции, правила рейтинга…
  entities/   сущности: типы API, запросы TanStack Query, карточки
  shared/     UI-кит, HTTP-клиент, утилиты, адреса страниц
```

- HTTP-клиент — `shared/api/http.ts`: база `/api/v1`, cookie-сессия, CSRF-токен в заголовке `X-CSRF-Token`, ошибки сервера превращаются в `ApiError` с ошибками полей.
- Меню кабинета по ролям — `widgets/cabinet-shell/model/nav.ts`, адреса страниц — `shared/config/routes.ts`.
- Компоненты — `shared/ui`. Все они в обеих темах собраны на странице `/design` (только в режиме разработки).
- Токены цвета и типографики — `app/styles/tokens.css`; цвета Tailwind по умолчанию отключены, только палитра брендбука.

## Правила интерфейса

- У каждого экрана с данными четыре состояния: загрузка (скелетон той же формы), пусто (с действием), ошибка (с «Повторить»), данные.
- Списки записей — таблицей `DataTable` с поиском и фильтрами над ней; фильтры каталога хранятся в адресе.
- Формы открываются в `Modal` (на телефоне — шторкой снизу); подтверждение — `ConfirmModal`, действие с причиной — `ReasonModal`.
- Ошибки полей от сервера показываются у полей, остальное — `FormAlert`.
- Даты и время — по Оренбургу (`Asia/Yekaterinburg`).
- Вёрстка проверяется на 375, 768, 1280 px и широком экране, в обеих темах.
