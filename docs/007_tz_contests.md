# Мини-ТЗ: соревнования (Ivan-003)

Ветка основной логики. Уведомления и журнал — параллельная ветка ([006_tz_notifications_audit.md](006_tz_notifications_audit.md)), статьи и файлы — [005_tz_files_news.md](005_tz_files_news.md).
Правила — [000_conventions.md](000_conventions.md). Фронтенд не трогается.

## Зачем

Первое звено главной цепочки кейса: **соревнование → заявка → занятое место → история → разряд → рейтинг**.

Продуктовая логика:
- **Организация сама проводит соревнования.** Верифицированный федерацией организатор создаёт и публикует свои соревнования без согласования — например, внутренние турниры вуза или компании.
- **Верификация соревнования — отдельно и по желанию.** Федерация может верифицировать конкретное соревнование: у него появляется значок «Верифицировано федерацией», и только такие соревнования влияют на рейтинг. Неверифицированное — просто событие доверенной организации.
- **При верификации федерация настраивает влияние на рейтинг** — сколько баллов даёт каждое место.
- **Федерация может создавать соревнования сама** — с полным функционалом: свои соревнования сразу верифицирует и настраивает рейтинг.
- Поля, которые задаёт только федерация (верификация, баллы за места), организатор **видит, но не меняет**.

Вкладки кабинетов (для логики, фронт не трогаем): у организатора «Соревнования» — первая вкладка, у федерации — вторая.

Что **не** входит в эту ветку:
- заявки участников, команды, судейские коллегии, результаты и протоколы — следующие этапы;
- расчёт рейтинга — этап рейтинга (здесь только настройка баллов за места);
- уведомления — места вызова помечены «→ уведомление», вызов добавляется после слияния ветки уведомлений;
- автоматическое открытие / закрытие регистрации по датам — этап «Контроль сроков»;
- календарные планы (ЕКП / КП) — по решению команды не ведём.

**Зависимость:** положение и фото используют модуль файлов из ветки статей (MinIO, публичный и приватный бакеты). Эта часть делается, когда файлы вольются в `main`; остальное — сразу.

## Как это задумано для рейтинга (на будущее)

Рейтинг будет считаться не из соревнований напрямую, а из отдельной сущности **«занятое место»** (этап результатов). Каждое занятое место хранит снимок на момент соревнования: спортсмен (или команда и её участники), соревнование, дисциплина, место, баллы по настройкам соревнования, возрастная группа по дате рождения на дату соревнования, академическая группа из профиля на ту дату, муниципалитет, организация, разряд, уровень соревнования, верифицировано ли оно.

Из этих снимков рейтинг потом можно считать разными способами: сумма, средневзвешенное, по возрастной или по академической группе, за скользящий год или сезон — без пересчёта истории.

Поэтому в этой ветке у соревнования уже есть: личное / командное, размер команды, баллы за места.

## Жизненный цикл

Организатор управляет **своими** соревнованиями полностью, федерация — **любыми**.

| Из | В | Действие |
|---|---|---|
| — | `draft` | создание |
| `draft` | `published` | опубликовать (обязательные поля заполнены) |
| `published` | `draft` | снять с публикации, пока регистрация не открывалась |
| `published`, `registration_closed` | `registration_open` | открыть регистрацию |
| `registration_open` | `registration_closed` | закрыть регистрацию |
| `published`, `registration_open`, `registration_closed` | `in_progress` | начать |
| `in_progress` | `completed` | завершить |
| `draft`, `published`, `registration_open`, `registration_closed` | `cancelled` | отменить, причина обязательна; → уведомление участникам (позже) |
| `completed`, `cancelled` | `archived` | в архив |

Неверный переход → 409 `invalid_status`. Каждый переход: блокировка строки и запись в журнал действий в одной транзакции.

### Правка и удаление
- **Правка** — организатор (своё) и федерация (любое) в любом статусе, кроме `archived`.
- **Удаление** — разрешено всегда, **кроме** `in_progress`, `completed`, `archived` (идёт или прошло — только отмена / архив) → иначе 409 `invalid_status`. Физическое удаление вместе со связями.

## Верификация

| Из | В | Кто | Что происходит |
|---|---|---|---|
| `not_requested`, `rejected` | `pending` | организатор-владелец | запрос верификации; встаёт в очередь федерации |
| любой | `verified` | федерация | по запросу или по своей инициативе (вариант Б); обязательна таблица `rating_points` — по умолчанию подставляется по уровню соревнования; → уведомление организатору |
| `pending` | `rejected` | федерация | причина обязательна; → уведомление организатору |
| `verified` | `not_requested` | федерация | снять верификацию (соревнование выпадает из рейтинга) |

- Соревнование федерации федерация верифицирует сама сразу при создании или позже.
- Баллы по умолчанию по уровню (из кейса, правятся при верификации):

| Уровень | 1 место | 2 место | 3 место |
|---|---:|---:|---:|
| Всероссийское | 100 | 80 | 60 |
| Межрегиональное | 60 | 45 | 30 |
| Региональное | 40 | 30 | 20 |

  Таблица — в домене как значения по умолчанию; федерация может задать любое число мест и любые баллы.
- **Правка после верификации.** Описание, фото, призовой фонд, положение, площадка, даты регистрации — верификацию не снимают. Дисциплина, уровень, личное / командное, размер команды, возрастные и академические группы, даты проведения — возвращают верификацию в `pending` (запись в журнале действий «изменены поля, влияющие на рейтинг»).
- Организатор не может передать `verification_*` и `rating_points` в теле — их нет в его схемах; в ответе они есть.

## Проверки при сохранении

422 `validation_error` с `fields` по именам полей:

| Нарушение | `fields` |
|---|---|
| ссылка на несуществующее или архивное значение справочника | `{"discipline_id": ["Выберите значение из справочника"]}` (по нужному полю, в т.ч. `age_group_ids`) |
| `ends_on < starts_on` | `{"ends_on": ["Не может быть раньше начала"]}` |
| `registration_closes_at <= registration_opens_at` | `{"registration_closes_at": ["Должно быть позже открытия"]}` |
| регистрация закрывается после начала соревнования | `{"registration_closes_at": ["Регистрация должна закрыться до начала соревнования"]}` |
| очно / смешанно без муниципалитета | `{"municipality_id": ["Укажите, где проводится"]}` |
| командное без размера команды или `min > max` | `{"team_size_max": ["Укажите размер команды"]}` / `{"team_size_max": ["Не может быть меньше минимума"]}` |
| у личного указан размер команды | `{"team_size_min": ["Только для командных соревнований"]}` |
| больше 10 фото | `{"photo_file_ids": ["Не больше 10 фото"]}` |
| `rating_points`: пусто, повторы мест, места не с 1, отрицательные баллы | `{"rating_points": ["…"]}` |

Новые ссылки — только на неархивные значения справочников. Для этого в доменный класс `Dictionary` добавляется `ensure_active(key, id)`.

## Файлы (после влития модуля файлов)
- Положение и фото загружаются через общий `POST /files`, в соревновании передаются их `id` (`regulations_file_id`, `photo_file_ids` — порядок = порядок в галерее).
- Пока соревнование `draft` — файлы в приватном бакете. При публикации — переносятся в публичный, при снятии с публикации / удалении — обратно / удаляются (через доменный класс файлов).
- В ответе у файлов есть `id` и `url`.

## Как реализовано (Ivan-003)
- Связи с группами — таблицы `contest_age_groups`, `contest_academic_groups` (без отдельных классов-моделей).
- Модуль файлов сделан в этой же ветке (вместо ветки статей). Вместо MinIO — **SeaweedFS**: community-MinIO больше не распространяется (dl.min.io отвечает 410, образы закрыты, репозиторий в архиве). Код работает через S3 API (клиент `minio`), настройки `s3_*` в `core/config.py`.
- Положение, до 10 фото и перенос файлов между бакетами — сделаны.
- «Не онлайн» определяется по названию формата (содержит «онлайн» — муниципалитет не нужен).
- Правка федерацией верификацию не сбрасывает (федерация — сама проверяющая); сбрасывает только правка организатором.
- Баллы по умолчанию для «Международного» уровня — как для «Всероссийского» (в кейсе нет), вопрос заказчику.
- Сжатое ТЗ для фронта — [009_front_contests.md](009_front_contests.md).

## Готово, когда
- Верифицированный организатор создаёт, публикует, правит и удаляет свои соревнования без согласования; они сразу видны в календаре.
- Организатор запрашивает верификацию; федерация видит очередь, верифицирует с баллами за места или отказывает с причиной; может верифицировать и без запроса, снять верификацию.
- Правка полей, влияющих на рейтинг, возвращает верификацию в «На проверке».
- Организатор не может менять верификацию и баллы (полей нет в его схемах), но видит их.
- Федерация создаёт своё соревнование и сразу его верифицирует.
- Нельзя удалить идущее, прошедшее или архивное соревнование; неверный переход → 409.
- Организатор не видит и не трогает чужие соревнования (404); не-организатор на `/organizer/*` → 403.
- Календарь без входа показывает публичные статусы со значком верификации, фильтры работают (в т.ч. «только верифицированные», «с призовым фондом»).
- Нельзя сослаться на архивное значение справочника; удалить используемое значение справочника → 409 `in_use` (впервые на реальных данных).
- После влития файлов: положение и до 10 фото, перенос между бакетами при публикации.
- История и аудит на каждое изменение статуса и верификации.
- Раздел «Соревнования» в `docs/001_api_map.md`, pyright — 0 ошибок, сценарий проходит в контейнере.
