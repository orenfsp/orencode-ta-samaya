Бэкенд ветки готов: соревнования, файлы, календарь. Контракт — [001_api_map.md](001_api_map.md), логика — [007](007_tz_contests.md), календарь — [008](008_calendar.md).
Тест: `python manage/fsp.py` → собрать → запустить. Аккаунты (пароль `Demo1234`): `federation@example.test`, `organizer@example.test`, `athlete@example.test`. Хранилище файлов отвечает на `http://localhost:9000`.

## 1. Правки того, что уже есть

**Справочники.** Бэкенд влит — мок больше не нужен: живой API по умолчанию (`isDictionaryMock` → только при явном `VITE_DICTIONARIES_API=mock` или убрать мок совсем).

**Календарь** (`entities/calendar`, `pages/calendar`, виджет на главной). Минспорта больше нет, лента = события ФСП + соревнования:
- типы: убрать `source`, `source_url`, `sources`, `SourceState`, `'ministry'`; у элемента ленты добавить `kind: 'event' | 'contest'`, `contest_id: number | null`, `status_title`, `is_verified`; `id` — строка;
- фильтр «источник» → `kind=event|contest`;
- клик: событие → карточка события (`GET /calendar/events/{id}`), соревнование → карточка соревнования (`GET /contests/{contest_id}`);
- у соревнований показать статус (`status_title`) и значок «Верифицировано федерацией» при `is_verified`;
- админка событий (`/admin/calendar/events`) — ответы без `source` / `source_url`, остальное как было. Перенести её пунктом «Календарь» в меню кабинета федерации вместо карточки на обзоре.

**Кабинеты.** `/cabinets/*` на бэкенде удалены (фронт их не использовал) — ничего не делать.

## 2. Навигация кабинетов
- Федерация: Обзор → **Соревнования** → Справочники → Календарь.
- Организатор: **Соревнования** (первая) → Обзор.

## 3. Соревнования

**Каталог** `GET /contests` — карточки, фото листаются по кругу, значок верификации, призовой фонд. Фильтры: дисциплина, уровень, формат, личное / командное, возрастная и академическая группа, муниципалитет, «только верифицированные», «с призовым фондом», даты, поиск, «ближайшие / прошедшие» (`period`).

**Карточка** `GET /contests/{id}` — всё о соревновании, положение (ссылка `regulations.url`), галерея, баллы за места у верифицированного.

**Организатор → «Соревнования»** (`/organizer/contests`):
- список своих со статусом и статусом верификации, фильтры по ним;
- создание / правка / удаление, кнопки переходов (таблица ниже), «Отменить» с причиной;
- «Запросить верификацию» (доступно при «Не запрошена» / «Отказано»), показать причину отказа;
- блок «Верификация и баллы» — только просмотр.

**Федерация → «Соревнования»** (`/admin/contests`):
- все соревнования + таб «Очередь верификации» (`verification_status=pending`);
- та же форма + выбор организатора (`organizer_id`); при создании можно сразу задать баллы → сразу верифицировано;
- «Верифицировать»: редактируемая таблица «место → баллы», по умолчанию из `GET /admin/contests/rating-points-defaults` по уровню соревнования; «Отказать» с причиной; «Снять верификацию»; «Изменить баллы» у верифицированного;
- история статусов и верификации (`/…/history`).

**Форма:**
- списки — `GET /dictionaries/{key}` (disciplines, contest_types, contest_levels, contest_formats, municipalities, age_groups, academic_groups); группы — мультивыбор;
- «Командное» → поля «размер команды от–до»; формат не «Онлайн» → муниципалитет обязателен;
- даты регистрации — ISO с часовым поясом (`+05:00`);
- призовой фонд: текст и/или сумма в рублях, оба необязательные;
- положение (PDF / DOCX) и до 10 фото — загрузка, см. раздел 4;
- 422 → подсветить поля из `error.fields`; 409 → тост.

**Кнопки по статусу:**

| Статус | Действия |
|---|---|
| Черновик | Опубликовать, Отменить, Удалить |
| Опубликовано | Открыть регистрацию, Начать, Снять с публикации, Отменить, Удалить |
| Регистрация открыта | Закрыть регистрацию, Начать, Отменить, Удалить |
| Регистрация закрыта | Открыть снова, Начать, Отменить, Удалить |
| Идёт | Завершить |
| Завершено | В архив |
| Отменено | В архив, Удалить |
| В архиве | только просмотр |

Правка организатором дисциплины, уровня, личного / командного, размера команды, групп или дат проведения у верифицированного соревнования отправит его обратно «На проверку» — стоит предупредить в форме.

## 4. Файлы
- `POST /files` (multipart, поле `file`, до 10 МБ) → `{id, original_name, content_type, size, url}`. Ошибки: 413 — большой файл, 415 — неподдерживаемый тип.
- `id` кладётся в `regulations_file_id` или `photo_file_ids` (порядок = порядок в галерее) при создании / правке соревнования.
- Показывать по готовому `url`: у опубликованных соревнований это прямая ссылка на хранилище (`localhost:9000`), у черновиков — `/api/v1/files/{id}` (откроется владельцу и федерации).

## Готово, когда
- Справочники работают с живым бэкендом без мока.
- Календарь показывает события ФСП и соревнования, клик ведёт в нужную карточку, значок верификации виден.
- Организатор проходит путь: создать с фото и положением → опубликовать → открыть регистрацию → запросить верификацию.
- Федерация видит очередь, верифицирует с баллами, отказывает с причиной, создаёт своё соревнование и сразу верифицирует.
- Каталог и карточка соревнований работают без входа, фильтры и галерея работают.
