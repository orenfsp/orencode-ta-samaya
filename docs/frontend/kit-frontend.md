# Frontend: React + свой UI-слой

Стек по умолчанию: React 18 + TypeScript + Vite + Tailwind v4. **Готовой дизайн-системы нет и не будет** — свой маленький слой токенов и примитивов пишем прямо в решении по брифу ниже. Если ТЗ даёт свой шаблон или UI-библиотеку — работай в ней, этот файл тогда только про UX и интеграцию. ТЗ даёт UI-кит или брендбук — он главнее брифа (сейчас — раздел «ФСП» ниже).

## ФСП: UI-кит из ТЗ — главнее брифа

Для этой задачи облик задаёт `agent/playbooks/fsp-ui-kit.md` (Федерация спортивного программирования). Где кит что-то говорит — делаем по киту, бриф §2–5 не применяем. От брифа остаётся только механика: токены в `tokens.css` через `@theme inline`, примитивы файлами в `src/ui/`, правила движения, 4 состояния экранов.

**Как читать метки кита**
- `[БРЕНДБУК]` — не обсуждается: палитра, шрифт, графика.
- `[САЙТ]` — состав блоков, пункты меню, тексты — как на сайте.
- `[ПРЕДЛОЖЕНИЕ]` — бери число из кита, но каждое — строкой в допущения SPEC (`A#`), в финальном отчёте — списком «сверить с макетами» (кит §11).
- Кит описывает весь сайт ФСП. Делаем **только экраны из ТЗ**, остальные компоненты кита не трогаем.

**Что меняется против брифа**

| | Бриф | ФСП |
|---|---|---|
| Цвет | индиго, серые с подмесом | ровно 5 цветов кита + белый: `#402FFF` синий, `#EC1D35` красный, `#EDEDED`, `#C8C9CA`, `#1B1C21` |
| Тема | тёмная | светлая база; `#1B1C21` — только hero, статистика, футер |
| Шрифт | Onest | **только JetBrains Mono** 400/500/700 с кириллицей; фолбэк `ui-monospace, "SFMono-Regular", Menlo, Consolas, monospace`. Офлайн — файлы шрифта в `public/fonts/` |
| Типографика | 15px база | шкала кита §2.4 (body 16/15, H1 44/28…), `letter-spacing` ≤ 0.02em, капс — только короткие метки. Моно шире — заголовки короче |
| Поверхности | §3 | граница 1px `#C8C9CA`, тени минимальные |
| Радиусы | 6…30 | 8px — карточки, поля, кнопки; 999px — бейджи |
| Сетка | ритм 2…40 | шаг 4 (4…96), контейнер 1200, поля 16/32, 12/4 колонки, брейкпоинты 640/1024/1280 = Tailwind `sm` / `lg` / `xl` |
| Движение | §5 | §5, но сдержанно: hover — лёгкий подъём или синяя обводка |

**Контраст — жёстко (кит §2.2, §10)**
- Синий текстом на тёмном — нельзя: на `#1B1C21` синий только заливкой с белым текстом.
- Красный — максимум один элемент на экран; на красной заливке только крупный жирный текст (от 18px bold); красный мелким текстом — нельзя.
- Второстепенный текст на тёмном — `#C8C9CA`. Цвет не единственный носитель смысла: онлайн/оффлайн и ошибки — ещё и текстом.

**Графика**
- Лого, «голова», карта России — только официальные файлы. Нет их в репо — попроси участника положить в `web/public/brand/`. Сам не скачивай и кодом не рисуй.
- «Линии-связи» (точки + соединения) фоном секции регионов можно рисовать SVG из палитры.
- Логотипы партнёров и фото — только официальные файлы, без них блок не выводим.

**Примитивы — из кита §5, только нужные экранам ТЗ** (вместо таблицы §4)
- `Button`: primary (синяя заливка, белый текст, 12×20, hover темнее ~8%), secondary (синяя обводка), danger (красная, только крупный текст), link, disabled (`#C8C9CA`). «Скачать документ» — secondary + иконка + подпись.
- Метки — не `Badge`, а четыре вида из `frontend/src/shared/ui/tags.tsx` (см. `frontend/RULES.md`): статус — точка + текст, свойство (Онлайн — синяя рамка, возраст) — тонкая рамка, вид сущности — иконка + моно, верификация — щит у названия. `Badge` — только счётчики.
- `Field`: подпись сверху, высота 44px, обводка `#C8C9CA`, focus 2px синий, ошибка — красная обводка **и** текст под полем. Согласие на ПДн — чекбокс со ссылкой.
- Карточки и строки (новость, событие, дисциплина, человек), календарь (mobile → список по датам), FAQ-аккордеон (открыт один), степпер, Header, Footer, cookie-баннер — состав и порядок полей ровно по киту §5.
- Focus-visible — outline 2px синий на всём интерактивном.

**Контент и тексты (кит §6–7, §10)**
- Данные не выдумываем: цифры, даты, суммы — только из ТЗ и кита. Чего нет — заглушка с пометкой `TODO`, а не правдоподобная выдумка.
- Даты: `13 октября 2026` в тексте, `09.10.2026` в карточках. «Оффлайн» через два «ф». `10 000 ₽` с неразрывным пробелом. Год в копирайте — динамически.
- Хлебные крошки на каждой странице; внешние ссылки — в новой вкладке с иконкой «наружу»; документ — иконка + название + тип + размер; списки — «Показать ещё», без бесконечного скролла.
- Строки интерфейса — в словарь (RU; EN — только если просит ТЗ).

**Не повторяем баги сайта (кит §9):** ссылки-пустышки (нет функции — нет ссылки), `user-scalable=no` в viewport, дубль названия в карточке события, захардкоженный год, одинаковая иконка вместо аватара (заглушка — инициалы на синем круге), пустые группы без «Состав формируется».

**Вопросы кита §12** — на разборе ТЗ: дешёвые закрываем допущением в SPEC (тема — светлая; неделя в календаре — Пн–Вс, хотя на сайте Вс–Сб), дорогие — один вопрос участнику.

## 0. Чистая комната

- Никаких сторонних и своих заготовленных дизайн-систем в репо решения: ни архивов в `vendor/`, ни пакетов из чужих монореп, ни скопированных исходников, даже если найдёшь их на диске. В чужие репозитории на машине не заглядывай.
- Всё визуальное пишешь с нуля по брифу §2–5: свои имена, свои файлы, свой код. Бриф — описание облика, а не код для копирования.
- В коде, комментариях, коммитах и README — никаких названий внешних дизайн-систем: это просто «UI-слой проекта».
- UI-кит из npm (shadcn, Radix, Headless UI) — только если участник прямо попросил.
- UI-кит или брендбук из ТЗ — не заготовка, а требование: по нему и работаем.

## 1. Скелет за 10 минут

```bash
npm create vite@latest web -- --template react-ts
cd web
npm i react-router-dom clsx
npm i -D tailwindcss @tailwindcss/vite
```

`vite.config.ts` — плагины `react()` и `tailwindcss()` (из `@tailwindcss/vite`). Шрифт — Onest (OFL, Google Fonts), если есть сеть; нет — `system-ui`. Для ФСП — JetBrains Mono (раздел «ФСП»).

```text
src/
├── styles/
│   ├── tokens.css     # переменные светлой и тёмной темы (§2)
│   └── index.css      # @import "tailwindcss", tokens, @theme, роли поверхностей (§3)
├── ui/                # свои примитивы (§4), по файлу на компонент
├── lib/api.ts         # клиент API (§8)
└── pages/…
```

`index.html` — тема на корне до первого кадра, иначе мигнёт: `<html lang="ru" data-theme="dark">` (для ФСП — `light`). Viewport без `user-scalable=no`.

Проверка скелета: `npm run build` проходит, страница с одной кнопкой открывается в стиле кита из ТЗ (для ФСП — светлая, JetBrains Mono, синяя primary), без кита — на `panel` в тёмной теме.

## 2. Токены — бриф

Все значения — переменные в `tokens.css`, утилиты Tailwind получают их через `@theme inline` (`--color-*`, `--spacing-*`, `--radius-*`, `--text-*`, `--shadow-*`, `--ease-*`). В компонентах — только утилиты, никаких `#hex`, `rgba()` и `px`.

**Цвет.** Один акцент — спокойный индиго (светлый, «воздушный», около `#8aa8ff`), к нему три роли:
- `accent` — заливка; текст поверх неё **тёмный** (почти чёрный), а не белый;
- `accent-text` — акцент как текст на поверхности: в светлой теме заметно темнее заливки (около `#4a62ae`), в тёмной — светлее;
- `accent-soft` — подложка выбора: акцент на 10–15% прозрачности.

Серые — не чистые: в каждый подмешано 2–4% акцента, иначе выглядят мёртвыми. Текст — не чистый чёрный и не чистый белый (около `#232323` и `#eeeeee`), вторичный текст — заметно светлее/темнее основного, но с контрастом ≥ 4.5. Семантика: успех — зелёный, ошибка — красный, предупреждение — **янтарь**, не жёлтый; в тёмной теме все три светлее. Отдельного синего «info» нет — он спорит с акцентом.

**Поверхности.** `bg` — фон под всем, `surface` — окно, `surface-2` — вложенная плашка, `border`. Тёмная тема — не чёрная: фон около `#191919`, окно около `#2a2a2a`. Ховер — полупрозрачный тинт цвета текста (~7%), а не сплошной серый.

**Ритм (зазоры по смыслу, а не по пикселям):** `hair` 2 · `inline` 4 · `snug` 6 · `base` 8 · `block` 12 · `group` 16 · `section` 24 · `page` 40. Поля экрана — около 28px на десктопе, 12–16px на телефоне.

**Радиусы — крупные:** 6 (мелочь) · 14 (поле, кнопка) · 20 (карточка) · 30 (панель, модалка) · pill. Мелкие радиусы делают панели квадратными.

**Типографика — ролями, в rem:** `micro` 11 · `caption` 12 · `compact` 13 · `body` **15 — база** · `body-lg` 17 · `title-sm` 18 · `title` 20 · `title-lg` 24 · `display` 32. Интерлиньяж: текст 1.5, заголовки 1.15–1.3. Крупному — отрицательный трекинг около −0.01em.

**Тени — мягкие и широкие:** размытие втрое больше сдвига, отрицательный разлёт, цвет — чёрный с лёгким подмесом акцента, не синий. Четыре высоты: `rest` (контрол), `raised` (карточка), `chrome` (шапка), `layer` (модалка).

## 3. Поверхности — бриф

Плоские поверхности, по классу на роль (`@utility panel { … }` в `index.css`), в компонентах — только роли.

| Роль | Где | Рецепт |
|---|---|---|
| `panel` | окно, сайдбар, основные панели | `surface`, граница `border`, тень `raised` |
| `overlay` | модалка, меню, тост — поверх чего угодно | `surface`, тень `layer` |
| `card` | карточка внутри панели | `surface-2` или граница без тени |
| `inset` | утопленное: поле, трек, скелет | тинт цвета текста ~8–14% |

Карточка внутри панели — без своей тени: глубину держат граница и подложка. Затемнение под модалкой слабое (~20–30% чёрного).

## 4. Примитивы — пиши только нужные главному сценарию

Каждый — один файл в `src/ui/`, 30–80 строк, без своих анимационных фреймворков.

| Нужно | Что написать |
|---|---|
| Кнопка | `Button`: `variant` fill / soft / ghost, `tone` accent / danger, `size`, `loading` (спиннер + блок кликов), рендер как `Link` при `to` |
| Кнопка-иконка | `IconButton` с обязательным `aria-label`; иконки — inline SVG `currentColor`, 1.75px штрих |
| Поле | `Field`: `label`, `hint`, `error` под полем, `required`; для пароля — показать/скрыть |
| Окно | `Modal` на нативном `<dialog>` (`showModal()` даёт фокус и Escape), `ConfirmModal` поверх него |
| Уведомление | `Toast` + `showToast(text, tone)` — один контейнер в корне, автоскрытие 4 с |
| Пусто / ошибка | `EmptyState`: заголовок, причина, действие; вариант ошибки с «Повторить» |
| Загрузка | `Skeleton` — блок `inset` с `animate-pulse`; спиннер — только внутри кнопки |
| Выбор | `Tabs` / `Segmented` — плашка выбора `accent-soft` + кольцо акцента ~20%; `Switch`, `Checkbox` — нативный input под стилями |

Тянуть больше — только когда экран реально его требует. Пропсы — минимум под сценарий, без «на будущее».

## 5. Движение — бриф

- Шкала: `quick` 150ms (ховер, цвет) · `smooth` 180ms (кнопки) · `layout` 220ms (панели) · `slow` 340ms (крупные слои).
- Кривые: стандартная `cubic-bezier(0.4, 0, 0.2, 1)`, выезд `cubic-bezier(0, 0, 0.2, 1)`, пружинка с перелётом `cubic-bezier(0.34, 1.56, 0.64, 1)` — только для мелкого (появление тоста, чек).
- Только `transform` и `opacity`. Кнопка при нажатии чуть проседает (`scale(0.97)`), модалка входит из `scale(0.96)` + прозрачности.
- Всё движение — за `@media (prefers-reduced-motion: reduce)`.

## 6. Каждый экран с данными — 4 состояния

загрузка (`Skeleton` формы будущего контента) · пусто (`EmptyState` с причиной и действием) · ошибка (`EmptyState` с «Повторить») · данные.
Белый экран и вечный спиннер — минус баллы.

## 7. Формы

- `Field` с `error` у поля; правила те же, что на бэке (длина, формат, обязательность).
- Ошибки сервера — человеческим текстом (409 → «уже существует», 401 → на логин).
- `Button loading` на время запроса — без двойной отправки. Enter отправляет (`<form onSubmit>`).

## 8. API

- Один клиент: base URL из `import.meta.env.VITE_API_URL` (дефолт `/api` за nginx-прокси), токен, 401 → на логин.
- Типы ответов — по контракту ТЗ; полей вне контракта не жди.
- Данные: простой `fetch` + свой хук или `@tanstack/react-query`, если списков много (кеш, повтор, `isPending` → скелет).
- Не хардкодь `localhost`: фронт откроют из контейнера или с другой машины. CORS — на бэке, или проксируй `/api` через nginx и Vite `server.proxy`.

## 9. Роутинг и сессия

- Прямой заход по URL и F5 работают на любой странице (SPA fallback в nginx, см. `delivery.md`).
- Защищённые маршруты без сессии → `/login?next=…` → после входа обратно.
- Сессия переживает перезагрузку, если ТЗ не говорит иначе.

## 10. Вёрстка

- Проверь 375px и десктоп: без горизонтального скролла, цели касания ≥ 44px, длинные тексты переносятся.
- Брейкпоинты — сетка Tailwind (`sm` / `md` / `lg`), без произвольных `max-[NNNpx]`.
- `data-testid` / id из ТЗ — буквально, это баллы автотестов.
- Фокус виден (`focus-visible` — кольцо `accent-text`), контраст текста ≥ 4.5 в обеих темах.

## 11. Проверка

- Главный сценарий руками в **прод-сборке** (`npm run build && npm run preview` или контейнер), не только в dev.
- Консоль браузера без ошибок на основных сценариях.
- `npm run build` и `tsc` зелёные до финала.
