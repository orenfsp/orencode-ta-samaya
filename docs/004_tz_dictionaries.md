# Мини-ТЗ: справочники (Ivan-002)

Ветка основной логики. Файлы, MinIO и новости в этой ветке не трогаются — они в параллельной ветке ([005_tz_files_news.md](005_tz_files_news.md)).
Правила — [000_conventions.md](000_conventions.md). Это общий фронт работы: пагинация и прочие нюансы — на усмотрение исполнителя. Фронтенд не трогается.

## Зачем

Справочник — список допустимых значений, которым пользуются все остальные данные: выпадающие списки в формах, фильтры реестра, правила разрядов и возрастов. Федерация правит значения сама через админку, без программиста. Никаких кодовых названий — только понятный текст.

- Набор справочников фиксирован в коде: один справочник = одна таблица = один класс. Создавать новые справочники через API нельзя — только записи внутри существующих.
- Другие таблицы ссылаются на запись справочника **внешним ключом на её `id`** (`contests.contest_type_id → dictionary_contest_types.id`). Переименование записи сразу видно везде, где она используется.
- Новую ссылку можно поставить только на неархивную запись. Старые ссылки на запись, ушедшую в архив, остаются рабочими.
- Записи можно создавать, переименовывать, менять и удалять. Архив — для сценария «нужен новый вариант, а старый больше не выбирать»: старое значение в архив, новое создаём. Архивное не показывается в выборе, но остаётся в истории.
- Удалить можно только запись, на которую никто не ссылается. Все внешние ключи на справочники — `ON DELETE RESTRICT`: БД сама не даёт удалить используемую запись, бэкенд отвечает 409 `in_use`, такую запись можно только архивировать. Неиспользуемая удаляется физически.
- Порядок значений федерация не меняет: списки отдаются в порядке добавления (по `id`). Демо-данные заведены в логичном порядке (разряды от старшего к младшему, группы по возрастанию), новые значения встают в конец.
- Разряды, судейские категории, возрастные группы — отдельные таблицы со своими полями-правилами (возраст, сроки), которые читают модули разрядов, заявок, рейтинга и контроля сроков. Цифры только здесь, в коде их нет.

## Модели — один справочник = одна таблица = один класс

Все в `infrastructure/`, файл на справочник. Всё, что относится к справочникам, явно помечено словом dictionary: файлы `dictionary_*.py`, классы `Dictionary*Model`, таблицы `dictionary_*`, схемы `Dictionary*Out/Create/Update`. Ключи в URL — без приставки (путь и так `/dictionaries/...`). Общие колонки у всех — миксин `DictionaryColumns` в `infrastructure/base.py`:

| Поле | Тип | Для чего |
|---|---|---|
| `id` | int, автоинкремент | |
| `name` | str(200) | само значение понятным текстом |
| `description` | text null | пояснение для федерации |
| `is_archived` | bool | скрыто из выбора |
| `created_at`, `updated_at` | timestamptz | |

Уникальность `name` среди неархивных — частичный уникальный индекс в каждой таблице, задаётся миксином.

| Ключ в URL | Файл / класс | Таблица | Свои поля |
|---|---|---|---|
| `disciplines` | `dictionary_discipline.py` / `DictionaryDisciplineModel` | `dictionary_disciplines` | — |
| `municipalities` | `dictionary_municipality.py` / `DictionaryMunicipalityModel` | `dictionary_municipalities` | — |
| `organization_types` | `dictionary_organization_type.py` / `DictionaryOrganizationTypeModel` | `dictionary_organization_types` | — |
| `academic_groups` | `dictionary_academic_group.py` / `DictionaryAcademicGroupModel` | `dictionary_academic_groups` | — |
| `age_groups` | `dictionary_age_group.py` / `DictionaryAgeGroupModel` | `dictionary_age_groups` | `min_age` (int null), `max_age` (int null) — хотя бы одна граница, пустая = без ограничения |
| `contest_types` | `dictionary_contest_type.py` / `DictionaryContestTypeModel` | `dictionary_contest_types` | — |
| `contest_levels` | `dictionary_contest_level.py` / `DictionaryContestLevelModel` | `dictionary_contest_levels` | — |
| `contest_formats` | `dictionary_contest_format.py` / `DictionaryContestFormatModel` | `dictionary_contest_formats` | — |
| `rank_types` | `dictionary_rank_type.py` / `DictionaryRankTypeModel` | `dictionary_rank_types` | `rank_kind` (str, `RankKind`: «Спортивный разряд» / «Юношеский разряд» / «Спортивное звание»), `min_age` (int null), `validity_months` (int null), `is_lifetime` (bool), `valid_until_age` (int null) |
| `judge_categories` | `dictionary_judge_category.py` / `DictionaryJudgeCategoryModel` | `dictionary_judge_categories` | `validity_months` (int null — бессрочно) |

`RankKind` — в `infrastructure/enums.py`, значения хранятся в БД как есть (понятный текст).

Проверки на уровне БД: `max_age >= min_age`, если заданы обе; у разряда либо `is_lifetime`, либо `validity_months`.

### Без отдельных настроек
Отдельной таблицы настроек нет:
- версия текста согласия на ПДн и пороги предупреждений о сроках (`[60, 30, 14, 7]` дней) — в `core/config.py`, меняются через переменные окружения;
- окно рейтинга (12 месяцев / сезон) — часть правил рейтинга, заводится на этапе рейтинга вместе с таблицей баллов.

## Область `backend/dictionaries/`

### Репозиторий `repositories/pg_dictionaries.py` — `DictionaryRepository`
Один класс, каждый метод принимает класс модели и работает с любым справочником:

| Метод | Что делает |
|---|---|
| `list(model, include_archived)` | в порядке добавления (по `id`) |
| `get(model, id)` | запись по id |
| `find_active(model, name)` | неархивная запись с таким названием |
| `add(item)` | сохранить новую |
| `update(model, id, values)` | изменить поля |
| `delete(model, id)` | удалить; `False`, если БД отказала из-за внешнего ключа (удаление в savepoint, ошибка целостности перехватывается) |

### Домен `domain/dictionaries.py` — класс `Dictionary`
- Реестр `REGISTRY`: ключ в URL → (название по-русски, класс модели), например `"contest_types": ("Типы соревнований", DictionaryContestTypeModel)`. Порядок ключей в реестре = порядок справочников в `GET /dictionaries`.
- Для админки:
  - `catalog()` — список справочников в порядке реестра;
  - `list(key, include_archived)`;
  - `create(key, fields, user_id, ip)` — название занято среди неархивных → 409 `name_taken`; бизнес-правила (ниже); аудит;
  - `update(key, id, fields, user_id, ip)` — можно менять всё, включая `name` (с той же проверкой уникальности); аудит со старыми и новыми значениями;
  - `archive(...)`, `restore(...)` — при восстановлении, если уже есть неархивное с тем же названием → 409 `name_taken`;
  - `delete(key, id, user_id, ip)` — если на запись кто-то ссылается (БД отказала по внешнему ключу) → 409 `in_use` «Значение используется — его можно только архивировать»; иначе физическое удаление и аудит с удалёнными значениями.
- Бизнес-правила. Нарушения возвращаются как 422 `validation_error` с `fields` — ключ = имя поля, значение = список сообщений по-русски, как у ошибок Pydantic. Фронт подсвечивает конкретное поле формы.

  | Нарушение | `fields` |
  |---|---|
  | разряд не пожизненный и без срока | `{"validity_months": ["Укажите срок действия"]}` |
  | пожизненный, но срок указан | `{"validity_months": ["У пожизненного звания срока нет"]}` |
  | `min_age` пустой не у «Спортивного звания» | `{"min_age": ["Укажите минимальный возраст"]}` |
  | `valid_until_age` не у «Юношеского разряда» | `{"valid_until_age": ["Только для юношеских разрядов"]}` |
  | возрастная группа без обеих границ | `{"min_age": ["Укажите хотя бы одну границу"]}` |
  | `max_age < min_age` | `{"max_age": ["Не может быть меньше «от»"]}` |

  409 `name_taken` (название занято среди неархивных) — без изменений; фронт сам показывает его у поля «Название».
- Для других модулей (добавляются по мере надобности): `ensure_active(key, id)` — запись есть и не в архиве, иначе 422 (перед тем как поставить новую ссылку); `rank_type(id)`, `judge_category(id)`, `age_groups_for(birth_date, on_date)`.

### Фичи и эндпоинты
Пути генерируются циклом по реестру фичи — у каждого справочника свой путь и своя точная схема в Swagger. Неизвестный справочник → 404 автоматически.

Фича `features/read/` — публично:

| Метод | Путь | Ответ |
|---|---|---|
| GET | `/dictionaries` | `[{key, title}]` в порядке `REGISTRY` |
| GET | `/dictionaries/{key}` — отдельный путь на каждый из 11 | неархивные значения в порядке добавления: `[{id, name, description, …свои поля}]` |

Фича `features/manage/` — федерация:

| Метод | Путь | Тело | Ответ |
|---|---|---|---|
| GET | `/admin/dictionaries/{key}?include_archived=` | — | список в порядке добавления, плюс `is_archived` |
| POST | `/admin/dictionaries/{key}` | `name`, `description?` + свои поля | 201, запись / 409 `name_taken` / 422 |
| PATCH | `/admin/dictionaries/{key}/{id}` | любые поля, все необязательные | запись / 409 `name_taken` / 422 |
| DELETE | `/admin/dictionaries/{key}/{id}` | — | 204 / 409 `in_use` |
| POST | `/admin/dictionaries/{key}/{id}/archive` | — | запись |
| POST | `/admin/dictionaries/{key}/{id}/restore` | — | запись / 409 `name_taken` |

Схемы: в каждой фиче одна общая тройка «создание / изменение / ответ» для 8 простых справочников и отдельные тройки для возрастных групп, разрядов и судейских категорий. В схемах — типы и диапазоны (возраст 0–100, срок > 0, длина названия), связи между полями — в домене.

Новые ошибки в `core/errors.py`: 409 `name_taken` — «Такое значение уже есть»; 409 `in_use` — «Значение используется — его можно только архивировать».
Аудит: `dictionary.create`, `dictionary.update`, `dictionary.delete`, `dictionary.archive`, `dictionary.restore` — с ключом справочника и значением.

## Заодно
- Ошибки валидации Pydantic по-русски: стандартные сообщения (`string_too_short`, `missing`, `int_parsing` и т. д.) переводятся в обработчике `core/errors.py`.

## Готово, когда
- Федерация создаёт, правит (включая название), удаляет, архивирует и восстанавливает записи любого справочника; публичный список архивные не показывает, порядок — как добавлены.
- Удаление используемого значения → 409 `in_use` (реальные ссылки появятся с соревнованиями и профилями; обработка — уже сейчас).
- Ошибки правил разряда и возрастной группы приходят как 422 в `fields` по именам полей.
- Для разрядов, категорий и возрастных групп нельзя сохранить значение без обязательных полей.
- Сроки разрядов и категорий, границы возрастных групп берутся только из БД.
- Не-федерация на `/admin/dictionaries*` → 403.
- Ошибки валидации приходят по-русски.
- Раздел «Справочники» в `docs/001_api_map.md`.
- pyright — 0 ошибок, сценарий проходит в контейнере.
