# Запуск и демо-база

Всё, что нужно, чтобы собрать бэкенд в один Docker-контейнер и поднять его с демо-данными. Внутри контейнера работают API, PostgreSQL, Redis, хранилище файлов SeaweedFS (S3 API) и Mailpit для писем.

| Файл | Что делает |
|---|---|
| `Dockerfile` | Образ: Python 3.12, PostgreSQL, Redis, SeaweedFS, Mailpit, шрифты для PDF. Копирует `backend/`, `infrastructure/` и файлы отсюда |
| `Dockerfile.dockerignore` | Что не попадает в образ: фронт, документация, `.git`, `fsp.py` |
| `entrypoint.sh` | Старт контейнера: поднимает PostgreSQL, Redis, SeaweedFS и Mailpit, запускает `bootstrap.py`, затем API |
| `fsp.py` | Меню для запуска контейнера с хоста: собрать, запустить, остановить |
| `bootstrap.py` | При каждом старте пересоздаёт схему из моделей, заливает `seed/seed.sql`, кладёт файлы в хранилище и выпускает документы |
| `s3.json` | Доступ к хранилищу: ключ приложения и публичное чтение бакета `fsp-public` |
| `seed/` | Демо-база: SQL и файлы к ней |

## Запуск через fsp.py

```bash
python manage/fsp.py
```

`fsp.py` — консольное меню для работы с контейнером с хоста. Запускается из любой папки: сам переходит в корень репозитория. Docker должен быть запущен, для сайта нужны Node.js 20+ и npm. Пункт выбирается стрелками ↑↓ и запускается Enter, можно и сразу цифрой. После выполнения меню появляется снова, выбор остаётся на последнем пункте. Пункты:

1. **Собрать / пересобрать.** Удаляет контейнер и старый образ `fsp`, собирает образ заново без кэша (`--no-cache`). Сборка из-за этого долгая, зато в образ гарантированно попадает свежий код без устаревших слоёв. Если сборка упала, причина видна в выводе выше. Затем в `frontend/` выполняются `npm install` и `npm run build` — зависимости сайта ставятся и сборка проверяется заранее.
2. **Запустить.** Удаляет прежний контейнер, если он был, и запускает новый `fsp` в фоне. Порты: 8000 — API и Swagger (`/docs`), 9000 — хранилище файлов (без него не открываются картинки и PDF), 8025 — Mailpit со всеми письмами, доступен только с этого компьютера. В контейнер передаются переменные окружения, заданные на хосте: `FSP_TELEGRAM_BOT_TOKEN`, `FSP_FRONTEND_URL`, `FSP_MAILPIT_URL` и `FSP_SMTP_HOST`, `FSP_SMTP_PORT`, `FSP_SMTP_TLS_MODE`, `FSP_SMTP_USERNAME`, `FSP_SMTP_PASSWORD`, `FSP_SMTP_SENDER`. Если задан `FSP_SMTP_HOST`, письма уходят на настоящую почту, а ссылка на Mailpit в письмах отключается; без него все письма оседают в Mailpit. Без `FSP_TELEGRAM_BOT_TOKEN` Telegram-бот не запускается, меню об этом предупреждает. После запуска меню печатает адрес Swagger, куда уходят письма и команду для логов: `docker logs -f fsp`. Если запустить не вышло, скорее всего образ ещё не собран — сначала пункт 1. Затем в фоне поднимается фронтенд (в `frontend/` сначала `npm install`, затем `npm run dev`) и меню печатает адрес сайта http://localhost:5173. Dev-сервер продолжает работать после выхода из меню, его вывод пишется в `fsp-frontend.log` во временной папке. Если порт 5173 уже занят, например фронтенд запущен вручную, второй сервер не поднимается.
3. **Остановить.** Гасит фронтенд, запущенный пунктом 2, и удаляет контейнер. Все данные пропадают, при следующем запуске база снова демо.

4. **Выход.** То же делают Esc, `q` и `Ctrl+C`.

Без меню то же самое делается из корня репозитория двумя командами:

```bash
docker build -f manage/Dockerfile -t fsp .
docker run -d --name fsp -p 8000:8000 -p 9000:9000 -p 127.0.0.1:8025:8025 fsp
```

## Демо-база

При каждом старте контейнера база возвращается в одно и то же чистое тестовое состояние: схема пересоздаётся, данные заливаются заново. Всё, что накликано руками, после перезапуска пропадает. Пароль всех демо-аккаунтов — `Demo1234`.

```
seed/
  seed.sql                  все данные по разделам, даты от current_date
  avatars/                  нейропортреты, по одному на аккаунт: <почта до @>.jpg
  regulations/              положения о соревнованиях: <код соревнования>.pdf
  orders/qualifications/    приказы и представления по разрядам и судейским категориям
  orders/squads/            приказы о составе сборных
  consents/                 согласия законных представителей: <почта до @>.pdf
  judge_documents/          документы судей к протоколу: записка, акт, протокол секретаря
```

- `object_key` в таблице `files` — путь файла внутри `seed/`. По нему `bootstrap.py` находит файл и кладёт в хранилище под тем же ключом.
- Дипломы, сертификаты, благодарности и справки файлами не хранятся. `seed.sql` только перечисляет, что выпустить (`seed_documents`), а выпускает их код приложения: так у документов настоящие номера и подписи.
- Новые демо-данные — новый раздел в `seed.sql`. Новый файл — в папку своего типа.
